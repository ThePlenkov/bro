# AGT-5 — Devin: manifest surface, project-local hook chain ownership

## Problem

Devin is the host this repository's own development runs on — the
plugin is also the reference implementation of the agent-plugins.org
manifest (`plugin.json` at `plugins/devin/bro/`, generated from the
repo-root manifest). Its distinguishing feature is the **project-local
hook chain**: `.devin/hooks.v1.json` in a target repo can own an
event, and `run.sh` must detect that and stay out of the way. The
spec pins the manifest mapping plus this ownership rule — it is the
subtlest part of the Devin surface.

## Design

### Surface: `manifest`, sync

`plugins/devin/bro/` carries `plugin.json` + `hooks.json` +
`hooks/run.sh`, all generated by `gen-plugins.ts` from the repo-root
sources. Install: `devin plugins install ThePlenkov/bro` (or
`ThePlenkov/bro#plugins/devin/bro`). `${DEVIN_PLUGIN_ROOT}` is the
root variable; `run.sh` accepts `PLUGIN_ROOT`/`CURSOR_PLUGIN_ROOT`/
`CLAUDE_PLUGIN_ROOT` fallbacks for shared invocations.

### Event mapping (HOOK_MATRIX `devin` row)

| bro event | Devin native | effects |
| --------- | ------------ | ------- |
| session-start | `SessionStart` | context |
| post-compaction | `PostCompaction` | context |
| prompt-submit | `UserPromptSubmit` | context |
| post-tool | `PostToolUse` (`^exec$`) | context, observe — outcome `field` (`tool_response.success`) |
| permission | `PermissionRequest` (`^exec$`) | approve |
| stop | `Stop` | block, context — `stopRefusal: 'block'` |
| pre-compact | — | declared gap |
| pre-tool | — | declared gap |

### Project-local chain ownership (the Devin-specific rule)

`run.sh`'s `project_devin_hook_owns_event` check: when the *target*
repo carries `.devin/hooks.v1.json` registering `hooks/run.sh <event>`
for the firing event, the plugin-installed copy exits immediately —
the project's own chain owns that event. Rationale: a repo that
vendored its own hook wiring must not get double probes from the
globally installed plugin. The check is event-scoped (only the
registered event defers), path-scoped (`SCRIPT_ROOT !=
DEVIN_PROJECT_ROOT`), and fail-closed toward *not* double-firing.

This is the contract's first **hook-ownership negotiation**: two bro
installs (global plugin + project-vendored) must not both answer one
event. Any future host with layered installs inherits the same rule —
declare it in the child spec, implement it in run.sh's preamble.

### Native functions leveraged

- **`plugin.json` (agent-plugins.org)** — Devin is a reference
  client for the portable manifest; the schema, keywords, and
  `hooks/` layout are the contract other clients copy.
- **`PostCompaction`** (not `PreCompact`) — Devin reports compaction
  *after* it happens; rehydration rides the post-event, so the
  pre-compact mark-clearing pattern used by Cursor/pi/omp has no
  Devin cell.
- **`tool_response.success` field** — the only manifest host whose
  post-tool payload carries the outcome verbatim (`outcome:
  'field'`); no split events, no synthesis needed.
- **`^exec$` tool matcher** — Devin's shell tool is `exec`; the
  matcher keeps hook volume to shell calls only.

## Requirements

- **R1** — `project_devin_hook_owns_event` stays event-scoped and
  path-scoped; a project chain owning `stop` must not silence
  `session-start`, and a foreign `hooks/run.sh` outside the project
  root must not claim ownership.
- **R2** — `plugins/devin/bro/` stays generated from repo-root
  `plugin.json`/`hooks.json` — never hand-edited.
- **R3** — Post-tool keeps `outcome: 'field'` — the journal reads
  `tool_response.success` verbatim; do not synthesize.
- **R4** — `PostCompaction` rehydration semantics preserved: the
  snapshot re-fires after compaction, matching session-start content.
- **R5** — Stop `decision:block` one-shot; Devin's block is enforced
  (`stopRefusal: 'block'`).

## Verify

- `host-matrix.test.ts` devin row green; `check:plugins` clean.
- `hooks.e2e.test.ts` Devin payload shapes (`tool_response.success`,

- Ownership: a fixture repo with `.devin/hooks.v1.json` shows the
