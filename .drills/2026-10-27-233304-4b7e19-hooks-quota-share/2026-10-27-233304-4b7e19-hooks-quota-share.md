# hooks share of the rate-limit burn (nested under 9f3c71)

## Question

Parent drill 9f3c71 established: metric is server-side only, two limiters,
hourly budget bucket on HH:01 marks, worker pace 33-56 requests/min with
71-97k tokens per inference call (`usage_update used=… size=262000` in
`.git/bro/agents/*.log`). Hooks run via `.devin/hooks.v1.json` →
`hooks/run.sh {session-start,post-compaction,prompt-submit,post-tool,stop}`
(fail-open, 0 failures today). Hook stdout for SessionStart and
UserPromptSubmit enters the model's context.

Sub-question: is the quota TOKEN-denominated? If yes, hook-injected context
(AGENTS.md + bro state + learn lessons + nudge lines) is billed on EVERY
request → hooks directly accelerate the wall. If request-denominated, hooks
cost only latency (already fixed by bro-36sx7 epic).

## Method (read-only)

1. **Token-vs-request discrimination**: mine `usage_update` lines across
   wall cycles today in `.git/bro/agents/*.log` (all files): extract
   per-minute token sums and request counts around wall onsets vs healthy
   windows. If walls align with a cumulative-token threshold (roughly
   stable across episodes) → token bucket; if with request counts →
   request bucket. Report both series with the candidate thresholds.
2. **Hook injection size**: read `hooks/run.sh` + whatever it sources
   (repo-local, read-only; do NOT execute anything that writes state —
   static reading only, or execute with a dry/no-op env if clearly safe)
   and estimate bytes/tokens of: SessionStart stdout (learn injections,
   bro state, session-start context), UserPromptSubmit stdout, PostToolUse
   stdout (matched ^exec$). Distinguish "enters model context" vs
   "local-only side effects" per devin hook semantics (stdout of
   SessionStart/UserPromptSubmit goes to the model).
   Cross-check empirically: message_nodes or prompt_history in
   `~/.local/share/devin/cli/sessions.db` (sqlite ro-mode) may show prompt
   payload sizes for today's worker sessions.
3. **Share calculation**: hook-injected tokens ÷ observed 71-97k per
   request → hooks' share of per-request cost; multiply by 33-56 req/min
   → tokens/min attributable to hooks. Compare with (1)'s threshold.

## Constraints

- READ-ONLY (repo, logs, db ro-mode). No hook execution if it mutates
  (bro state writes, bd claims, pulse arming) — prefer static reading.
- Timestamps only from this run's output; clock check at start.
- If undecidable (e.g. usage fields lack prompt/completion split), state
  confidence + falsifier; do not overclaim.

## Return contract

1. Verdict: token-denominated / request-denominated / undecidable (+confidence, evidence rows).
2. Hooks' share of per-request tokens (%), with method.
3. Actionable: if hooks are a material share → which injection to trim (learn injection? state? nudge) — bead-worthy item.
4. prevention_plan[] (action/scope/sink/owner/evidence).
