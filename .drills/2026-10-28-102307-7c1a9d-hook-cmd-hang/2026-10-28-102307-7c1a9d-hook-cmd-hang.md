# drill: hook cmd/run hangs (nested under 4b7e19)

## Question

Perf aggregates (48h, `.git/bro/hooks/perf/*.jsonl`): event `cmd`,
n=2683, **avg 28868ms > p95 4345ms** — a small tail drags the mean far
above p95, i.e. some `cmd` hook invocations ran for MINUTES. Also all 79
`"failed":true` records in 48h are `event=cmd, probe=run`. Meanwhile
worker-log lines "timed out after 10s" total ~3.5k (2977 in pre-today
logs vs 543 in today-touched; today's fresh workers = 0) — is the
timeout-line family the SAME phenomenon or separate (hook-timeout 10s
budget vs cmd probe slowness)?

## Method (read-only, subagent)

1. **Tail census**: parse every `.git/bro/hooks/perf/*.jsonl` (48h
   cutoff = ts now-172800000): extract `cmd` records with ms, build the
   real distribution — count buckets (>10s, >30s, >60s, >5min), top-20
   slowest with ts/session-id. Compute honest mean/p95/p99/max.
2. **What ran**: for the slow/failed cmd records identify the command —
   fields in the record (probe/connector/detail?), plus static reading of
   the cmd hook path in `packages/cli/src/commands/hooks.ts` (what
   `cmd` executes: bd? bro state? git? — static read only, DO NOT execute
   mutating hooks). Map each slow record to its command class.
3. **Correlation**: cross-ref slowest ts against known infra events —
   `.git/bro/loop.out`, `.git/bro/daemon.log`, `.git/bro/timeout*.log`
   if any, bd/dolt fsck ETIMEDOUT mentions (grep by time window ±2min).
   Do the 79 failed records cluster on a command or a time (e.g., dolt
   fsck storms)?
4. **Timeout-lines relationship**: sample a few "timed out after 10s"
   lines — which hook event/probe produced them (event field in line?),
   dated today vs old — is it the 10s command-hook budget (hooks.ts
   timeout values in .devin/hooks.v1.json: 10/15/20s) firing on cmd?
5. **Impact**: were any of these hangs inside FLEET worker sessions
   (post-tool latency = model waiting)? Estimate wasted wall-clock:
   sum(ms>10s) per day → minutes lost × workers.
